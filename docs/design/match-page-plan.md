# 比赛页设计与事件进度条重设计

> 状态：设计稿，未动代码。前置：`docs/design/stadium-plan.md` 已完成，本文接比赛模块。
> 最后更新：2026-10-22

## 0. 两个前提

1. **没有临场指挥。** 引擎先算完整场再按时钟推流，赛场内的换人/移位到不了已算完的比赛。触发条件 + 延后语义就是这条约束的产物。
2. **不绑架用户。** 直播是可选的观赛，不是必须值守的控制台。任何时刻都能「直接看结果」，看完不自动跳转。

这两条决定了直播页的定位：**一段可快进、可随时离开的回放**，而不是实时指挥台。

两种壳（`MatchLiveView` 330 行 / `TacticalMatchDetail` 595 行）已经漂移：战报有解说、替补席、三路控制力，直播只有球场和侧栏。

## 2. 事件进度条的根因

现在的 `MatchTimeline` 把**比赛时钟线性映射成横轴**，于是所有问题都在同一根轴：

- 把 0–90 分钟按比例铺开，事件密度极不均匀，标记互相挤压；
- 补时长度可变（`45+N1`、`90+N2`），只能塞进轨道里当"额外的视觉分钟"，于是出现"45 分钟补时窗口只有 1 分钟宽"；
- 为了在两段常规时间之间留出补时与中场，填充必须**拆成两段**（`match-timeline.tsx:406-417`），否则绿色和琥珀色混成"muddy olive"；
- 半个半场的哨声刻度，**标签写 90+5' 但位置在 89+N1+N2**（`:452-470`），标签和位置对不上，是设计出来的；
- 进球/黄牌/换人挤在一条 3px 轨道上方，只能靠图标区分；
- 横向拖拽既和页面纵向滚动打架，又让整块要 `select-none` + 指针捕获。

**根因不是丑，是把一维线性轴当成了比赛的表达方式。** 它要同时承载：常规时间、变长补时、事件密度、比分变化——四件事互相冲突，每打一个补丁就多一层。

## 3. 重设计：拆成两个东西

### 3.1 战报 —— 竖向「比赛脊柱」

不在时间轴上定位，**按顺序排列**。竖向列表天然不重叠、天然适配移动端，并且和页面滚动方向一致。

```
┌ 比赛脊柱 ──────────────────────────── 1 – 0 ┐
│                                             │
│  ●  38'   进球   Lei Peng          1–0   ╱  │
│  ○  31'   黄牌   张伟                   ╱   │
│  ⇄  12'   换人   李四 → 王五          ╱    │
│                                             │
│ ── 上半场结束 · 45+2' ──────────────────    │
│                                             │
│  ○  45+1' 黄牌   陈九                       │
│  ●  52'   进球   Wang Wu           1–1  ─╲  │
│                                             │
└─────────────────────────────────────────────┘
                        ↑ 右侧比分阶梯（24px）
```

**规格**

| 元素 | 规格 |
|---|---|
| 脊柱 | 2px 竖线，`border-outline-variant/20`，穿过事件节点；章与章之间断开 8px |
| 节点 | 28px 圆，按类型：进球=实心主色、黄/红牌=描边 `warning`/`error`、换人=双箭头、伤病=加号 |
| 分钟 | `font-mono text-label tabular-nums`，固定 56px 宽右对齐，`45+2'` 与 `90'` 同宽不跳动 |
| 章标题 | 吸顶，`text-kicker uppercase tracking-[0.3em]`，左侧一句说明（上半场 / 上半场补时 / 下半场 / 补时） |
| 比分阶梯 | 右侧 24px 宽 SVG 折线，每个进球抬一格；主队进球向上、客队向下，整场情绪一屏读完 |
| 事件行 | 56 + 28 + 正文，行高 44px；hover 整行 `bg-surface-container/40` |

**为什么补时不再是特例**：补时事件就是同一列表里的普通行，分钟写成 `45+2'`。不需要额外色块、不需要额外宽度、不需要两段填充。

### 3.2 直播 —— 只读进度轨

直播要的是"还剩多久"，不是"读完整场"。所以保留横向，但**只做一根轨**：

```
上半场 ████████████░░░░  61'      ● 38'  Lei Peng
                 ↑ 补时斜纹
```

- 三段：1H / 2H / 补时（补时段用 45° 斜纹，宽度按实际补时分钟比例）
- 进球用 6px 小圆钉在轨上，点一下跳球场快照
- **不拖拽**：直播没有"回看"语义，拖拽反而让人以为能控制比赛
- 只读，`role="progressbar"`，不是 `slider`

战报如果需要回看，用脊柱点击 + 球场跳转，不需要第二根横向拖拽条。

### 3.3 两个产物共用的东西

- `match-timeline.ts` 里的**分组与格式化**（`formatMatchMinute`、事件分类、章节边界）全部复用
- `minuteToPercent` / `visualMinute` / `InjuryBand` / `TickMark` / 两段填充 —— **只有直播轨用得到**，脊柱一行都不需要
- 颜色语义一套：主队 `primary`、客队 `on-surface-variant`、危险 `error`、警告 `warning`

**净效果**：脊柱不需要任何坐标映射，只按时间排序 + 章节切分。这一类 bug（错位、混色、标签对不上）从根上消失。

## 4. 交互

- 点事件行 → 球场切到该分钟快照 + 解说定位到该条（现在拖拽条和事件列表是两套坐标，合并成一套）
- 键盘：`↑`/`↓` 在事件间移动，`Enter` 选中；脊柱本身是 `role="list"`
- 直播结束：停在原地，出现「查看完整战报」，不自动跳转

## 5. 统一壳（合并两套壳）

一份组件树 + `mode`：

```
<MatchPage mode="live" | "report">
  MatchHeader        面包屑 / 轮次 / 类型徽章 / 战术入口
  MatchScoreHero     队徽 + 队名 + 比分 + 状态      ← 队色 4% 径向渐变
  MatchVerdict       4 格结论 + 三路控制力条        ← live 时换成分钟进度
  MatchBody
    MatchPitchStage  球场（球员视图 / 数据视图）
    MatchAside       场地天气 / 关键事件 / 三路
  MatchSpine | MatchProgressRail
  MatchFooter        替补席 / 下一场
```

直播与战报只差三件事：自动推进、连接状态、出口按钮。**合并必须单独一个提交**，先把两边差异逐条列全（解说、替补席、连接状态、空态、比分 hero 的 props），否则会丢功能。

## 7. 验收标准

- 一屏能读完 90 分钟的事件，任意窗口宽度（≥1024）无重叠、无横向滚动
- 补时事件与常规事件同列，顺序正确，分钟显示 `45+2'`
- 战报里不存在任何"分钟 → 横向位置"的映射
- 点事件行，球场与解说同步到该分钟
- 键盘可完全操作脊柱
- 直播页全程可「直接看结果」，结束后不跳转
- 比赛页与球队页共用同一套页宽、标题、字号 token（`grep 'text-\[10px\]'` 在该目录下为 0）

**四个会丢功能的风险点**（合并时逐个核对）：

1. 直播的**连接状态 / 断线提示**——战报没有这套 UI，丢了用户就不知道比赛是不是卡住了
2. 战报的**替补席**——直播没有，合并后直播也该有
3. 战报的**解说**与**关键事件**在侧栏、直播的解说在底部——合并后统一放左栏底部
4. `MatchScoreHero` 的 props 两边不一致，取并集时要保持两边都不崩

**目标结构**

```
<MatchPage mode="live" | "report">
  <article className="max-w-7xl mx-auto space-y-4">
    {mode === 'live' && <ConnectionBanner />}
    <MatchScoreHero ... />
    <MatchVerdict />              {/* D2；当前用战报的结论卡 */}
    <div className="grid lg:grid-cols-[1fr_300px] gap-4 items-start">
      <main className="space-y-3">
        <PitchStage />            {/* 视图切换 + MatchPitch */}
        <MatchSpine />            {/* D3；当前用 MatchTimeline */}
        <LiveCommentary />
        <MatchSubstitutes />
      </main>
      <aside className="space-y-3">
        <MatchInfoPanel /> <MatchKeyEvents /> <StatsResult />
      </aside>
    </div>
    {mode === 'report' && <MatchFooter />}

```

**执行顺序**：先建 `MatchPage` 壳 + 把 `MatchScoreHero` 的 props 取并集 → 迁直播（差异小）→ 迁战报（删赛前阵型球场、把结论卡与解说搬到目标位置）→ 删掉两个旧组件 → 跑覆盖两边的测试。每一步都必须是独立可运行的提交。

- **D1 收尾修正**（`380ac30`、`74f5906`）：页宽 1120、右栏 300、脊柱/解说的阅读宽度 720、pitch 上限 800 且标记缩放到 0.8。**记录一条硬约束：pitch 的标记是固定尺寸（52px 圆 + 10px 名字），容器窄于约 760px 必然重叠，再窄只能换标记，不能靠调容器宽度。**
- **D2 已完成**（`2fefb79`）：`MatchVerdict` 结论区 + 三路条，推导逻辑在 `match-verdict.ts`（纯函数，10 个单测）。结论按「有球权没比分 → 决胜路 → 射门效率 → 一球之差 → 平局」的顺序取一条，每句都由记录在案的数字拼成；数据缺失时整条不渲染，不用 0 填充。
- **D3 已完成**（`a84ce95` 脊柱、`0b68952` 进度轨）：战报换成竖向「比赛脊柱」（`MatchSpine.tsx`），直播换成只读进度轨（`MatchProgressRail.tsx`），`MatchTimeline.tsx` 删除。
  - 脊柱不做任何坐标映射：事件按章节（上半场 / 上半场补时 / 下半场 / 补时）分组，分钟在固定 56px 列里，`45+2'` 就是一条普通行。进球行右侧带当时比分（由 markers 顺序折叠得出，不靠数数）。
  - 进度轨三段（1H / 2H / 补时斜纹按实际补时分钟占宽）+ 进球钉，**不可拖拽**，`role="progressbar"`。点进球钉只回看一帧，下一个事件把播放头带回最新帧——所以直播不再有「用户正在拖拽」这个抑制自动推进的 ref。
  - `match-timeline.spec.ts` **没有迁移**：它本来就是纯函数测试（1630 行、89 个用例），不渲染组件，所以组件换掉后全部照样绿。之前估的「1627 行要一起迁移」是错的——真正要删的只有组件本身。
  - 顺手删掉 `TacticalMatchDetail.tsx` 里 D1 遗留的 38 行死接口 `SnapshotData_dead` 和一个未使用的 import。
  - 遗留：`TacticalMatchDetail.tsx` 里的 `Date.now()`（`react-hooks/purity`）是 D1 之前就有的，本轮没动。
- **D3 修正**（`84756e3`、`b3262ae`）：用户否掉了两处设计，都已执行。
  - **两个模式共用一条进度带**：进度轨改成五分钟一格的格子带（单事件显图标、多事件显三点 + 气泡列表、补时各半场单独一格 `45+'`/`90+'`），战报也换用它 —— 脊柱 `MatchSpine.tsx` 删除。理由：同一场比赛两套导航隐喻（战报列表、直播格子），玩家换个页面就得重新学事件在哪；**有序阅读本来就由下方解说流承担**，进度带只负责"我在哪、发生过什么"。
  - **删除比赛结论**（`MatchVerdict.tsx` + `match-verdict.ts` + spec 10 个用例）：它的一句话结论和数据总结卡是同一个事实的两种写法，而总结卡印的是数字本身，比替玩家下结论更诚实。
  - 结果：web 测试 860 → 850（删掉的正好是 verdict 的 10 个用例），`match-timeline.spec.ts` 依旧全绿。
