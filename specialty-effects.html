阅读须知

  • 引擎原则 (v2.7+): 引擎不再"特挑"特技球员参与事件。所有选人环节是 attribute 评估，特技只对被选中的球员生效 — 你可以理解为"如果一个 AERIAL_THREAT 球员被选为头球射门者，他有 1.10× 头球加成；不是引擎故意找他来头球"。
  • buff 范围 (5 种) — 每个 hook 都有, 第一个 badge:
    个人 buff 个人 lane buff 全队 aura (product, cap) 全队 decision (max × depth) 全队 product (cubed, cap)
    个人 buff = 只对该球员自己的某次动作生效。个人 lane buff = 该球员对自己所在 lane 的贡献放大。全队 = 在该 event 上聚合场上所有持该 hook 的球员。
  • event 类别 (7 种) — 每个 hook 都有, 第二个 badge:
    射门评分 pushDuel 力量 lane 站位 / 推进 犯规 / 受伤 门将扑救 点球 / 任意球 队伍 aura
  • 个人 vs 全队: TACKLER / WALL 的 push_defense 同时有 个人 buff (1.15/1.18) + 全队 product (cubed, cap 1.80)。两个维度叠加。WALL / SWEEPER_KEEPER 的 command_defense 是 该球员给全队的 aura (per-player aura)，不是"自己的属性 buff"。
  • 个人 vs 全队 (续) — 关键区分:
    • 个人 buff: "该球员的某次动作评分 × 系数" (e.g. POACHER 补射 1.15 — POACHER 球员自己补射的评分)
    • 个人 lane buff: "该球员对自己所在 lane 强度的贡献 × 系数" (e.g. WALL defense_lane 1.10 — 该 WALL 对自己 lane defense 的贡献放大 10%, 但 lane 上还有非-WALL 球员稀释)
    • 全队 aura (aura, product, cap): "该球员给全队某 event × product" (e.g. SWEEPER_KEEPER command_defense 1.05 — GK 给全队 defense lane × 1.05, cap 1.20 永远触不到)
    • 全队 decision (max × depth): "场上 N 个 holder, 取 max × (1 + 0.05 × (N-1)), 无上限" (e.g. TACKLER midfield_control 1.20 — 决策类, 3 Silver = 1.32)
    • 全队 product (cubed, cap): "场上 N 个 holder 的系数相乘, cap" (e.g. TACKLER push_defense 1.15 — 强度类, 3 Silver = 1.52, 4 Silver 触顶 1.80)
  • 位置 vs 特技 (generator 层): 特技分配是 GK vs outfield 二分 — GK 只 roll 2 个 GK 特技 (SAVING_MASTER / SWEEPER_KEEPER), outfield 10 个位置 (ST/CF/LW/RW/AM/CM/DM/LB/RB/CB) 共享 10 个 outfield 特技池, 每个 outfield 位置 roll 到每个 outfield 特技的概率完全一样 (1/10 = 10%)。"出没位置" 字段写的是 心智最匹配的位置, 不是引擎限制 — e.g. WALL 心智适合 CB/LB/RB (1v1 站位型防守), 但 DM/CM 也能 roll, 引擎效果一样生效。SAVING_MASTER / SWEEPER_KEEPER 只能给 GK, 其他 10 个 outfield 特技不能给 GK (engine 层 wall) — 引擎看到 GK 球员持 outfield code 不会触发任何 hook。
  • v2.8 / v2.8.1 找补: 凡带 v2.8 找补 或 v2.8.1 找补 标签的都是这一轮新加的。v2.8 = 6 个 nerf specialty 找补 + 1v1 wire。v2.8.1 = 心智 cleanup (删 POACHER attack_lane / SPEEDSTER shot_long, 加 AERIAL_THREAT 守方 debuff)。

如何读懂这张表
  • 每个 hook 都有 2 个显眼 badge: 范围 (个人/个人 lane/全队 aura/全队 decision/全队 product) + event 类别 (射门/对抗/lane 站位/犯规/gk/setpiece/aura)。
  • "个人 buff" 跟 "个人 lane buff" 的区别: 前者乘到"该球员的某次动作评分" (e.g. POACHER 补射), 后者乘到"该球员对自己所在 lane 强度的贡献" (e.g. WALL defense_lane 1.10)。前者是 per-shot, 后者是 per-lane 加性。
  • "全队 aura" 跟 "全队 product/decision" 的区别: aura = 该球员给全队某 event × product, cap; product/decision = 场上所有持该 hook 的球员聚合。
  • v2.8 找补 / v2.8.1 找补 = v2.7 削弱后新加的 hook, 对应 commit 6e008a3 (v2.8) / 待 commit (v2.8.1)。
  • v2.5 wired / v2.6 移位 = 之前 commit 接上的或移位的 hook。
  • tier 数字 (Gold/Silver/Bronze) 都是实际生效值 (已经走 applyTierMultiplier(base, tier)), 不是 base 系数。tier 概率: outfield Gold 5% / Silver 15% / Bronze 30% / No Spec 50% (50% 球员有特技); GK (v2.8.1) Gold 1% / Silver 3% / Bronze 6% / No Spec 90% (只有 10% 门将有特技, 5× 稀有 — 守门员是场上最稀缺位置, GK with spec 应该像 "discovery")。条件化 tier 比例 (Gold 10% / Silver 30% / Bronze 60% of "has spec") 两边相同, 只 NO_SPEC ceiling 不同。
  • coef < 1 的 (如 foul_rate 0.50) 走同一公式但含义翻转: tier 越高, 减免越多 — Gold COMPOSED 实际犯规率仅 37.9%。
